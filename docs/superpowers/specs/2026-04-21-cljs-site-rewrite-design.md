# CLJS Site Rewrite — shadow-cljs + Reagent + Garden

**Date:** 2026-04-21
**Status:** Draft
**Replaces:** Astro 6 static site

## Motivation

Align the site toolchain with the rest of gl1tch (Babashka/Clojure). Astro is a dead-end build step — shadow-cljs gives a live REPL into the running site, same as bb gives for the CLI. Everything becomes Clojure data: content, styles, diagrams, components.

## Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Compiler | shadow-cljs | CLJS compilation, dev server, nREPL |
| UI | Reagent | Reactive components via hiccup |
| Routing | Reitit | Client-side hash routing |
| Styling | Garden | CSS-in-Clojure, token-based |
| Syntax Highlighting | Highlight.js | Code blocks, custom glitch language def |
| Diagrams | Custom DSL | Flowchart specs → hiccup SVG |
| Deployment | GitHub Pages | Static files, same as today |
| SEO | Headless Chrome prerender | bb task captures static HTML per route |

## Content Format

All content is hiccup EDN generated by glitch workflows.

### Docs (`content/docs/getting-started.edn`)

```clojure

 :description "Install glitch and run your first workflow"
 :order 1
 :sections
 [{:heading "Install"
   :level 2
   :body [[:p "Install via Homebrew:"]
          [:code {:lang "bash"} "brew install 8op-org/tap/glitch"]]}
  {:heading "Your first workflow"
   :level 2
   :body [[:p "Create a " [:code ".glitch"] " file:"]
          [:code {:lang "clojure"} "(step :greet (shell \"echo hello\"))"]
          [:diagram {:type :flowchart}
           [:node :write "Write .glitch"]
           [:node :run "glitch run"]
           [:edge :write :run]]]}]}
```

### Content Principles

- Body content is hiccup vectors — renderers pass them straight to Reagent
- Diagrams inline via `:diagram` tags, resolved by the diagram component
- TOC derived at render time by walking `:sections` for headings
- Sidebar derived from docs index (all doc EDN sorted by `:order`)
- No build-time sidebar generation — it's runtime data

## Routing

Reitit browser router with hash-based routing (GitHub Pages compatible):

```clojure
(def routes
  [["/" {:view pages.home/page}]
   ["/docs" {:view pages.docs/index}]
   ["/docs/:slug" {:view pages.docs/page}]
   ["/labs" {:view pages.labs/index}]
   ["/labs/:slug" {:view pages.labs/page}]
   ["/changelog" {:view pages.changelog/page}]])
```

- Top nav: Home | Docs | Labs | Changelog
- Docs: sidebar (left) + content (center) + TOC (right float)
- Labs index: card list with title, description, duration badge
- Lab pages: single column, step numbers, progress indicator at top
- Page transitions: Reitit swaps the `:view` component, no full reloads

## Diagram DSL

Flowcharts only for v1. A small Clojure DSL that takes declarative specs and emits hiccup SVG.

### Spec Format

```clojure
{:direction :lr  ;; or :tb
 :nodes [{:id :write :label "Write .glitch"}
         {:id :run :label "glitch run"}
         {:id :verify :label "Gates pass"}]
 :edges [[:write :run] [:run :verify]]}
```

### Layout Engine (`diagrams/core.cljs`)

- Topological sort to determine layers
- Even spacing within and between layers
- Arrow paths: straight lines, 90-degree bends for multi-layer jumps
- Returns positioned nodes + edge paths

### SVG Primitives (`diagrams/svg.cljs`)

- `(box {:x :y :w :h :label :style})` — rounded rect + centered text
- `(arrow {:path [...] :style})` — polyline with arrowhead marker
- `(label {:x :y :text})` — standalone text

Colors pull from Garden theme tokens.

### Future Expansion

Sequence diagrams, state diagrams, auto-sizing — add when a real doc needs them.

- All REPL-editable — change a token, see it instantly

## Glitch Pipeline Integration

### Modular Workflows

Each pipeline operation is a standalone workflow, callable from REPL or composed by the orchestrator:

```
workflows/site/
├── generate-doc.glitch        # takes slug, outputs EDN to content/docs/
├── generate-lab.glitch        # takes slug, outputs EDN to content/labs/
├── generate-changelog.glitch  # takes date range, outputs EDN to content/changelog/
├── gate-syntax.glitch         # edn/read-string validation
├── gate-structure.glitch      # schema check (required keys, types, nesting)
├── gate-hallucinations.glitch # grounding check against source code
├── gate-links.glitch          # walk hiccup for [:a {:href}], verify routes exist
├── sync.glitch                # orchestrator — generate + gates for all content
└── deploy.glitch              # build + prerender + commit + push
```

### REPL Usage

```bash
# Generate a single doc
glitch run workflows/site/generate-doc.glitch --param slug=getting-started

# Gate-check one file
glitch run workflows/site/gate-syntax.glitch --param file=content/docs/getting-started.edn

# Run all gates
glitch run workflows/site/gate-syntax.glitch

# Full sync
glitch run workflows/site/sync.glitch
```

### Gate Changes

| Gate | Before (Markdown) | After (EDN) |
|------|-------------------|-------------|
| syntax | markdown lint | `clojure.edn/read-string` — if it reads, it's valid |
| structure | heading hierarchy regex | schema validation (required keys, types, nesting) |
| hallucinations | string matching against source | same grounding check, reads EDN `:body` vectors |
| links | regex for markdown links | walk hiccup tree for `[:a {:href}]` |
| sidebar | diff sidebar HTML vs manifest | removed — sidebar is runtime-derived |

### Build Tasks (bb.edn)

- `site:dev` → `npx shadow-cljs watch app` (dev server + nREPL)
- `site:build` → `npx shadow-cljs release app` + prerender
- `site:repl` → connect nREPL to running dev server

### Content Conventions

`site/conventions.md` updated with EDN/hiccup examples for LLM prompts. Schema examples included in prompt context so LLMs produce valid structures.

## SEO

bb task runs headless Chrome against the dev server, captures each route as static HTML, writes to `resources/public/`. GitHub Pages serves static HTML, SPA hydrates on load. Crawlers get full content without JS execution.
